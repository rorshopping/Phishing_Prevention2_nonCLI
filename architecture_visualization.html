1. Execution Flow Comparison

▶ Quick Test run_test.py

0 📤 Precondition: Set target emails via update_emails.py --old @gmail.com --new @yourdomain.com
🔄 Swaps email substrings in phishguard_test.db employees table. Sets both email and email_hash columns. One-time setup.
▼
1 🏛 Create throwaway client — picks random name from 10 German company names (Muller & Sohne GmbH, Schmidt Metallbau AG, etc.)
💾 Inserts into clients table: contact_email=admin@test.de, industry=Technology, country=DE, campaigns_per_year=25
▼
2 👥 Create 4 employees — hardcoded with German names and roles:
💼 Anja Schneider (CFO, Finance) • Felix Wagner (Engineer, Engineering) • Lena Hoffmann (HR Manager, HR) • Klaus Weber (IT Admin, IT)
✉ Email format: {base_local}+{alias}@{domain} — e.g. bob+anja@company.com
▼
3 📋 Create draft Campaign — named "4-Email {HH:MM}", status=draft, difficulty=easy
▼
4 🧠 Hardcoded plan dict — maps employee_id to scenario_type:
🎯 Anja → ceo_fraud • Felix → cloud_notification • Lena → dropbox_share • Klaus → credential_harvest
▼
5 ⚙ ExecutionAgent.execute_campaign(id, plan) — same agent as production, but with pre-made plan & no monitoring/vishing follow-up
✅ Prints: "Result: Success/Failed", Gophish campaign IDs, final status

▶ Production Full Flow orchestrator.py

0 📦 Trigger mechanisms — 3 ways to start a production campaign:
⏰ Scheduler: asyncio loop runs every 300s in FastAPI (auto-startup when GOPHISH_API_KEY set)
📡 API: POST /clients/{id}/campaigns triggers orchestrated campaign
⌨ CLI: python -m src.cli.main campaign run --client-id <id>
▼
1 🔀 Orchestrator checks pacing — run_scheduled_campaigns() iterates active clients, calls _client_needs_campaign()
📅 Checks: campaigns_this_year < campaigns_per_year • campaigns_this_year < expected_by_month • days_since_last > max(14, 365/campaigns_per_year)
▼
2 🤖 CampaignPlanner.plan_campaign(client, employees) — AI-powered strategy design
📝 LLM prompt: "Design phishing campaign for {company}, {industry}, {country}, {employee_count} employees. Recent threats: {...}"
⚖ Returns JSON: difficulty (easy/medium/hard), scenario_weights (0–100 per scenario), rationale
🎯 Per-employee: decide_scenario_for_employee() uses GROUP_SCENARIO_AFFINITY (e.g. Finance → invoice_fraud, ceo_fraud, credential_harvest) weighted by LLM strategy
▼
3 📋 Create Campaign record — status=scheduled, stores plan name, difficulty, scheduled_date (+1 hour), logs "campaign_planned" audit action
▼
4 ⚙ ExecutionAgent.execute_campaign(id, plan) — identical agent to Quick Test, but plan comes from LLM planner
▼
5 🎤 VishingAgent (conditional) — if client.vishing_enabled, triggers AI voice calls for each employee
🏠 Scenarios: tech_support, bank_fraud, hr_benefits, vendor_call, ceo_urgence. Uses ElevenLabs TTS (fallback: Twilio TTS). Simulates if no Twilio configured.
▼
6 🔍 MonitoringAgent (ongoing) — polls Gophish every 300s for all running campaigns
📊 Updates CampaignResult: email_opened, link_clicked, credentials_submitted, ip_address. Detects completion. Logs "failure_alert" if clicks detected.
🏁 Finalizes: status=completed, aggregates sent/clicked/fail counts, triggers alert if clicked>0

2. ExecutionAgent Internals src/agents/execution_agent.py

Both paths funnel through ExecutionAgent.execute_campaign(). For each scenario group, one Gophish campaign is created: 

ExecutionAgent.execute_campaign(campaign_id, plan?)
    |
    +-- 1. Load campaign from DB
    +-- 2. Set status = running
    +-- 3. Load active employees for this client
    +-- 4. _ensure_landing_pages()  --> Gophish Page (captures creds + passwords)
    +-- 5. _ensure_smtp_profile() --> Gophish SMTP (Gmail, created once, reused)
    +-- 6. Parse employee assignments from plan
    |      - No plan? All employees get ScenarioType.bank_transfer
    |      - Map planner scenarios via PLANNER_TO_EMAIL_SCENARIO dict
    +-- 7. _group_employees_by_scenario()
    |      - Groups employees so each Gophish campaign gets ONE template
    |      - Prevents "identical emails" bug
    |
    +-- FOR each scenario group:
          |
          +-- 8. Build target context (name, role, dept, group, linkedin, public_data)
          +-- 9. _generate_single_template()
          |      - Sanitizes context (first name only) for LLM privacy
          |      - Queries Client table for company name
          |      - Calls generate_email(scenario, ctx, company)  --> LLM via OpenRouter
          |      - Fallback 1: Groq (if FALLBACK_LLM_API_KEY set)
          |      - Fallback 2: hardcoded German templates in _fallback_email()
          |      - Strips <body> tags, saves as Gophish Template
          |
          +-- 10. _create_group_for_targets() --> Gophish Group (targets with email, name, position)
          +-- 11. _launch_gophish_campaign()
          |      - POST /campaigns with {group, template, page, smtp, url, launch_date}
          |      - URL: http://localhost:8080 (Gophish phishing server)
          +-- 12. Collect Gophish IDs (campaign, group, template)
    |
    +-- 13. Store comma-separated IDs: gophish_campaign_id, gophish_group_id, gophish_template_id
    +-- 14. _create_result_records() --> CampaignResult rows (one per employee, personalization context)
    +-- 15. AuditLog: "campaign_executed" with scenario_count, employee_count, gophish_ids
    +-- 16. Commit transaction

4. Production Campaign Lifecycle

Full lifecycle from scheduler tick to campaign completion:

Scheduler Tick (every 300s)
    |
    +-- monitor_all_active_campaigns()  --> polls Gophish, updates results, finalizes completed
    +-- run_scheduled_campaigns()      --> checks pacing, launches new campaigns
    |
    +-- _client_needs_campaign(client)
    |    Returns True ONLY if ALL 3 gates pass. Any gate failing = skip this client.
    |
    |    Gate 1: Annual hard cap
    |    SELECT COUNT(*) FROM campaigns
    |      WHERE client_id = X AND created_at >= Jan 1 this year
    |    |
    |    +-- campaigns_this_year >= client.campaigns_per_year?
    |    |     Example: cpty=25, ran 25 already = True --> SKIP (hard ceiling)
    |    |     Example: cpty=25, ran 12 so far = False --> continue to Gate 2
    |    |
    |    +-- [True] --> return False (skip)
    |
    |    Gate 2: Monthly pacing
    |    target_per_month = max(1, round(campaigns_per_year / 12))
    |    months_elapsed  = max(1, current_month - 1)
    |    expected_by_now = target_per_month * months_elapsed
    |    |
    |    +-- campaigns_this_year >= expected_by_now?
    |    |     Example: cpty=25. target=ceil(25/12)=2. July = month 7,
    |    |       months_elapsed=6. expected=2*6=12. Ran 12+? --> SKIP (pacing)
    |    |       Ran only 8? --> below target, continue to Gate 3
    |    |
    |    +-- [True] --> return False (skip, wait for next month)
    |
    |    Gate 3: Minimum interval
    |    Load most recent completed campaign date
    |    min_interval = max(14, 365 // campaigns_per_year)
    |    |
    |    +-- days_since_last < min_interval?
    |    |     Example: cpty=25. min_interval=max(14, 365//25)=max(14,14)=14
    |    |       Last campaign was 6 days ago. 6 < 14? --> SKIP (too soon)
    |    |     Example: cpty=5.  min_interval=max(14, 365//5)=max(14,73)=73
    |    |       Last campaign was 60 days ago. 60 < 73? --> SKIP
    |    |       Last campaign was 80 days ago. 80 < 73? --> False, continue
    |    |
    |    +-- [True] --> return False (skip, not enough days since last)
    |
    |    +-- All gates passed --> return True (needs campaign!)
    |
    +-- [True] run_client_campaign(client_id)
               |
               +-- Load client + employees
               +-- CampaignPlanner.plan_campaign()
               +-- Save Campaign (status=scheduled)
               +-- ExecutionAgent.execute_campaign()
               |     |
               |     +-- [ON ERROR] rollback, status back to draft
               |
               +-- [IF vishing_enabled] VishingAgent.trigger_vishing_call() per employee
               +-- Log "campaign_completed" audit action
               +-- Commit

... meanwhile, on subsequent scheduler ticks ...

monitor_all_active_campaigns()
    |
    +-- SELECT * FROM campaigns WHERE status = running
    +-- For each:
         +-- _fetch_gophish_results() --> GET /campaigns/{id} for each Gophish ID
         +-- _update_results()
         |     - Match by email_hash (HMAC-SHA256 of recipient email)
         |     - Set email_opened, link_clicked, credentials_submitted, ip_address
         +-- _detect_completion()
         |     - All results in completed status (Sent/Opened/Clicked)?
         +-- [IF complete] _finalize_campaign()
         |     - status = completed, completed_at = now
         |     - Aggregate sent/clicked/fail counts
         |     - [IF clicked > 0] Log "failure_alert" (Slack/email integration TBD)
         +-- Log "campaign_monitored" audit action

5. Key Files Reference

run_test.py Python
Quick Test entry point. Creates throwaway client + 4 employees, hardcodes plan, calls ExecutionAgent directly, prints results. No server needed. Gophish must be running.
debug_execution2.py Python
Single-employee debug script. Richer output: prints client/employee/campaign IDs before execution, then updated campaign fields (gophish IDs), CampaignResult count, and AuditLog entries after execution.
debug_execution.py Python
Minimal execution re-run. Finds most recent campaign in DB, calls ExecutionAgent.execute_campaign(id) without a plan (uses fallback: all employees get bank_transfer). Useful for re-running failed campaigns.
src/agents/orchestrator.py Agent
Production orchestrator. Composes all 4 agents. run_scheduled_campaigns() iterates clients, checks pacing, launches campaigns. monitor_all_active_campaigns() polls Gophish. Manages vishing scheduling per client.
src/agents/campaign_planner.py Agent
LLM-powered campaign strategy. Generates difficulty + scenario weights via LangChain/ChatOpenAI. Per-employee scenario selection uses GROUP_SCENARIO_AFFINITY weighted by LLM strategy. Falls back to equal weights if LLM fails.
src/agents/execution_agent.py Agent
Gophish resource creator. Groups employees by scenario, generates email templates (LLM + fallback), creates Gophish groups/templates/pages/SMTP, launches campaigns. Called by both quick test and production.
src/agents/monitoring_agent.py Agent
Campaign result poller. Fetches Gophish results, matches by email_hash, updates CampaignResult (opens/clicks/creds). Detects completion, finalizes campaigns, logs failure alerts for clicks.
src/agents/vishing_agent.py Agent
Voice phishing caller. Generates AI scripts per scenario, synthesizes via ElevenLabs, places calls via Twilio. Simulates if Twilio not configured. Logs VishingSession records.
src/engine/email_builder.py Engine
Email generation core. Scenario prompts (German), LLM invocation with 2-provider fallback, 10 hardcoded German fallback templates. Maps planner scenario names to ScenarioType enums.
src/engine/personalizer.py Engine
Employee research tool. SerpAPI-powered LinkedIn + news search per employee. Caches results in-memory. Falls back gracefully if SERPAPI_API_KEY not set.
src/engine/gophish.py API
Low-level Gophish HTTP client. Wraps httpx with Bearer auth. Methods for groups, templates, pages, SMTP profiles, campaigns. Custom GophishClientError for API errors.
src/services/gophish_service.py Service
Service layer over GophishClient. Higher-level interface used by agents. Delegates to gophish.py for all API calls. Thin wrapper.
src/database/models.py DB
SQLAlchemy ORM models. 6 tables: Client, Employee, Campaign, CampaignResult, VishingSession, AuditLog. Campaign stores Gophish IDs as comma-separated strings (gophish_campaign_id).
src/main.py API
FastAPI server. Routes: /clients, /campaigns, /webhooks, /vishing, /health. Starts background scheduler on startup (if GOPHISH_API_KEY set). CORS enabled, request logging middleware.
update_emails.py Python
Email update utility. Bulk substring replacement or single-employee set. Direct SQLite writes to phishguard_test.db. Run once before quick test to set target delivery addresses.

External integrations:
  LLM API       OpenRouter (primary) → Groq (fallback) → hardcoded templates
  Search API    SerpAPI (LinkedIn + news enrichment, optional)
  Voice API     Twilio (outbound calls) + ElevenLabs (TTS, optional)
  Email send   Gmail SMTP via Gophish (sends to any recipient)
  Webhooks     /webhooks/gophish (event callbacks, optional)
               /webhooks/twilio (call status callbacks, optional)
Key architectural insight: The Quick Test skips the Orchestrator, Planner, Monitoring, and Vishing layers entirely. It instantiates ExecutionAgent directly with a hardcoded plan. This makes it useful for verifying that Gophish works and emails deliver, but gives zero insight into pacing, LLM strategy, result tracking, or vishing follow-up.
